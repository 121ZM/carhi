## ★ 「只投屏一块内容」的可用官方能力（2026-10-17 查 SDK 头文件实证）

大哥提「开小窗口，投屏就投小窗内容」。查 `native_avscreen_capture.h` / `_base.h`（SDK 26）：

| 能力 | 接口 | since | 备注 |
|---|---|---|---|
| **区域采集** | `OH_AVScreenCapture_SetCaptureArea(capture, displayId, OH_Rect*)` | **20** | 采集前后都能调、可运行中动态改；坐标非负、不可跨屏；失败沿用上次区域 |
| **系统选择器** | `SetPickerMode` + `PresentPicker` | 22 | 系统级 UI 让用户选「屏幕/窗口/应用」，采集**不中断**地换源 |
| **应用级采集** | `PickerMode = OH_CAPTURE_PICKER_MODE_APP_ONLY`(=3) | **26.0.0** | 只列应用；用户选哪个 App 就只录它 |
| 窗口级采集 | `missionIDs` + `captureMode=OH_CAPTURE_SPECIFIED_WINDOW`(=2) | 10 | 需目标窗口 missionID，普通应用拿不到别人的 |
| 选择结果回调 | `SetSelectionCallback` + `GetCaptureTypeSelected`(0屏/1窗口/2应用) | 20 | 在采集启动前注册 |

- `OH_Rect{x,y,width,height}` 定义在 `native_avscreen_capture_base.h:388`。
- **应用自建全局悬浮窗仍然判死**（`EntryAbility.ets:383` 实测：声明 FLOAT_VIEW 导致装机失败 9568289，全部悬浮窗权限要求系统应用）。⇒ 字面「自己开小窗」不可行；但**系统智慧多窗把 CarHi 拖成小窗**是用户侧系统能力，不需要 App 申请权限，此时用 `SetCaptureArea` 按小窗屏幕坐标采集即可实现「只投小窗」。

## ★ 画中画（PiP）判定：不可用于本项目（2026-10-17 查 `@ohos.PiPWindow.d.ts` 实证）

大哥问「像影视 App 一样点一下就自动变小窗」——那是系统 PiP。查证结果：

- **不需要特殊权限**（整个 d.ts 无 `@permission` 标注），`PiPWindow.isPiPEnabled()` + `create()` 即可，@since 11。
- **但 `PiPConfiguration.componentController: XComponentController` 是必填字段** ⇒ PiP 窗口只能承载 **XComponent**（视频/自绘 native 内容）。ArkUI 组件（高德 `MapViewComponent`）**塞不进去**。
- **`PiPWindowInfo` 只有 `{ windowId, size }`，没有屏幕坐标**；`window.getWindowProperties()` 只有实例方法，无法按 windowId 反查矩形 ⇒ **拿不到 PiP 窗口在屏幕上的 x/y**，`SetCaptureArea` 无从下手。
- 普通应用也**没有**「请求系统把我变成悬浮小窗」的 API（`StartOptions.supportWindowModes` 是启动别的应用时用的，直板机也不支持 FLOATING）。

⇒ 结论：**影视 App 那条路对我们无效**（内容类型不匹配 + 坐标不可得）。

**可行替代（按实用度排序）**：
1. **应用级采集**（`OH_CAPTURE_PICKER_MODE_APP_ONLY`，API 26）：弹系统选择器选「高德」，车机只显示高德，手机随便用别的 App。最接近大哥要的体验，且不需要小窗。
2. **把自己缩到角落**：`win.resize()` + `win.moveWindowTo()`（普通应用可用），配合区域采集。但**不能浮在别的 App 之上** —— 切走就被覆盖，车机那块会变成别人的画面。
3. **系统分屏**（用户手动）：CarHi 占一半、高德占一半，区域采集 CarHi 那半。
4. 系统智慧多窗手动拖成小窗（用户操作，非代码触发）。

## ★ 小窗横屏（2026-10-17 追加，同一功能的下半段）

**官方硬约束（`@ohos.window.d.ts` 实证）**：
- `window.resize()`：**只在 `WindowStatusType.FLOATING` 下生效**，其他模式报 **1300002**。
- `window.moveWindowTo()`：文档明确「**非 freeform 模式的主窗口不支持**」，同样 1300002。
- ⇒ **普通应用无法自己把主窗口变成/变成小尺寸悬浮窗**，只能等用户用系统「智慧多窗」拖。
  这与 `FLOAT_VIEW` 判死（装机失败 9568289）是同一条权限边界的两个侧面。

**枚举**：`UNDEFINED=0 / FULL_SCREEN=1 / MAXIMIZE=2 / MINIMIZE=3 / **FLOATING=4** / SPLIT_SCREEN=5`

**实现（`Index.ets`）**：
- `applySmallWindowLandscape()`：`getWindowStatus()===FLOATING` → `setPreferredOrientation(LANDSCAPE)`
  → `resize(短边×0.9, ×9/16)` → `moveWindowTo(0, 短边×0.1)` → `applyRegionFromWindow()`。
  非 FLOATING 时只提示「先用智慧多窗拖成小窗」并仍下发一次区域（全屏时=整屏，无害）。
- `restorePortrait()`：关闭开关时切回 `PORTRAIT`（EntryAbility 启动时设的就是竖屏）。
- `windowStatusChange` 监听：用户拖成小窗的**瞬间自动接管**，不用再点一次。
- **坑：尺寸基准必须用屏幕短边**（`Math.min(d.width, d.height)`）。`setPreferredOrientation`
  之后 display 的 width/height 可能已按横屏互换，直接用 `d.width` 会算出几乎占满整屏、
  甚至超过屏幕高度的"小窗"。
- 做成 16:9 的意义：区域宽高比 = 车机 1280×720 ⇒ **不变形、无黑边**，绕开
  `StrategyForFillMode`（ASPECT_SCALE_FIT / SCALE_TO_FILL）的取舍。

**构建**：`bash tools/build.sh debug` → BUILD SUCCESSFUL（增量 38s），仅既有告警。

**未解**：小窗横屏后 ArkUI 页面仍是竖排设置列表，横过来会很挤；车机看到的是设置页而非地图。
若要让小窗显示地图，需再做「小窗专用横屏视图」。

## ★★ 独立投屏子窗口（2026-10-17 晚，大哥定的最终形态）

**需求**：主窗口保留设置页，投屏画面放到**单独的窗口**里。

**为什么不是别的两条路**：
- `window.resize()` / `moveWindowTo()` 官方语义：**只在 `WindowStatusType.FLOATING` 下生效**，
  主窗口全屏调用报 **1300002**（`moveWindowTo` 文档还写明"非 freeform 模式的主窗口不支持"）。
- 全局悬浮窗 `TYPE_FLOAT`：`FLOAT_VIEW` / `SYSTEM_FLOAT_WINDOW` / `USE_FLOAT_BALL` 全是
  **system_basic** 级，普通自签名证书**没有对应 ACL**，声明即**装机失败 9568289**。
  要走通只有 AGC 申请受限权限 + 企业开发者认证 + 重新签发带 ACL 的 profile（不是改代码能解决的）。

**采用方案**：`UIAbilityContext.windowStage.createSubWindowWithOptions(name, options)` @since 11。
- `SubWindowOptions`：`title`(必填) / `decorEnabled`(必填) / `isModal?` / `modalityType?` /
  **`windowRect?: Rect`** / `maximizeSupported?` / `zLevel?` / `outlineEnabled?`
- **`windowRect` 能在创建时直接指定位置尺寸** —— 一次做成 16:9，完全不依赖 `resize()`。
- 子窗口**不需要任何权限**。

**实现**：
- 新增 `pages/CastWindow.ets`（`@Entry`，内嵌 `MapPage`，`onExit` 里 `destroyWindow()` 关自己），
  在 `main_pages.json` 注册。
- `Index.ets`：`castWin: window.Window` + `@State castWinOpen`（静态字段必须镜像成 @State 才会刷新 UI），
  `openCastWindow()`（按屏幕短边算 0.9 宽 × 16:9，`windowRect` 一次到位，再 `loadContent` +
  `setPreferredOrientation(LANDSCAPE)`）、`closeCastWindow()`、`toggleCastWindow()`；
  采集区域用子窗口 rect；`stopAppCast()` 里一并关窗。

**边界（明确告知大哥）**：子窗口仍属本应用，**切到其他 App 时整个应用不可见**，
此时区域采集录到的是"盖在这块区域上的别的内容"。真正浮在别人之上仍需系统悬浮窗权限。

## ★★★ 修正：「悬浮窗判死」是我判断错了 —— floatView 才是官方能力（2026-10-17 晚）

大哥指出「很多软件都支持悬浮窗口」，复查后确认**我之前的结论有误**。

- 之前只查了 `window.createWindow({windowType: TYPE_FLOAT})` 这条老路（需 `SYSTEM_FLOAT_WINDOW`），
  就下了"判死"结论 —— **漏了 HarmonyOS 26 新增的 `@ohos.window.floatView`**（@since 26.0.0）。
- 实际能力齐全（`@ohos.window.floatView.d.ts` 实证）：
  - `isFloatViewEnabled()` 设备支持检查
  - `create({context, templateType, isConfirmOnClose})` —— **无 @permission 标注**
  - `setUIContext(path)` / `setUIContextByName(name)` —— **可加载任意 ArkUI 页面**
    （地图能放进去！这一点和 PiP 完全不同，PiP 强制 `XComponentController`）
  - `setWindowSize({width,height})` —— 可设 16:9
  - `start()` —— **需要 `FLOAT_VIEW`**
  - `getWindowProperties()` → `FloatViewProperties { templateType, windowId, displayId,
    **windowRect**, windowScale, avoidArea, inSidebar }` —— **有屏幕坐标，可直接喂 SetCaptureArea**
  - `onRectChange(cb: FloatViewRectChangeInfo { windowRect, windowScale, reason })` —— 拖动/缩放跟随
  - `getFloatViewLimits(type)` → `{ minSize, maxSize, ratioLimits }`
  - `stop()` / `setFloatViewVisibilityInApp(bool)` / `onStateChange`
- `FloatViewTemplateType`：`ROUNDED_RECTANGLE=0` / `HORIZONTAL_BAR=1`
- **权限分级（`PermissionDefinitions.json` 实证）**：
  | 权限 | grantMode | level | since |
  |---|---|---|---|
  | `FLOAT_VIEW` | **user_grant** | system_basic | 26.0.0 |
  | `USE_FLOAT_BALL` | system_grant | system_basic | 20 |
  | `SYSTEM_FLOAT_WINDOW` | system_grant | system_basic | 7 |
  ⇒ 全是 system_basic，普通签名证书**无 ACL**；**AGC 申请受限权限通过前写进 module.json5
  会装机失败 9568289**。但注意：`create()` 不要权限、**只有 `start()` 要** —— 所以代码可以
  先写好，运行时 try/catch 降级。

**已实现**：`Index.ets` 加 `openFloatWindow()`；`openCastWindow()` 改为
「**先试系统悬浮窗 → 失败自动降级应用子窗口**」；`closeCastWindow()` 先 `ctl.stop()`。
`module.json5` **暂不声明 FLOAT_VIEW**（避免装机失败）。权限批下来后只需加一条 requestPermissions。

**★ 方法论教训**：判断"某能力能不能用"时，**不能只查一个 API 就下"判死"结论** ——
同一功能在新版本 SDK 可能换了实现路径（`window.createWindow(TYPE_FLOAT)` → `floatView`）。
可靠做法：先看 `@kit.*.d.ts` 的**完整导出列表**（那里 `floatingBall` / `floatView` 一直摆着），
再逐个查具体接口，比凭记忆猜 API 名字靠谱得多。
