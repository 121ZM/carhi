## 编译修掉的 10 个真实问题（都是编译器/声明文件报的，不是猜的）

1. `GET_BLUETOOTH_INFO` 不是合法权限 → 本方案音频走系统 A2DP，App 不碰蓝牙 API，**直接删权限**
2. `socket.TCPSocketServerListenOptions` 不存在 → `srv.listen(address: NetAddress)`
3. `TCPSocketConnection` **没有** `read()` / `setExtraOptions()` → 收数据用 `on('message')`；
   `setExtraOptions` 在 **server** 上设（`TCPNoDelay` 要在这里开）
4. ArkTS 无视频编码 API（见上）
5. ArkTS 屏幕采集只能录文件（见上）
6. `startBackgroundRunning` 返回 `void` 不是 taskId；**任务类型必须选 `AUDIO_RECORDING`**
   （官方用途写着 "recording and screen capture in the background"），
   `DATA_TRANSFER` 是"上传下载"且 10 分钟不更新进度会被取消 —— 选错就废
7. `OH_AVSCREEN_CAPTURE_ErrCode` ≠ `OH_AVErrCode`；成功常量分别是
   `AV_SCREEN_CAPTURE_ERR_OK` / `AV_ERR_OK`，必须分开声明变量
8. native 模块**默认导入会退化成 `any`**（触发 `arkts-no-any-unknown`）→ 必须用具名导入
9. `wantAgent.WantAgent` 不存在 → `WantAgent` 是 `@kit.AbilityKit` 的独立导出
10. `@Builder` 不接受 `content: () => void` 形式的 lambda 参数 →
    改用 `@Component` + `@BuilderParam` + 尾随闭包

## 另外两个"读文档才能发现"的点

- **`PushInputBuffer` 官方注释写明是 "in buffer mode" 专用** → Surface 模式下

# 2026-10-10（续）· 签名链路打通

## 大哥的要求

「E:\ZM\CarHi 证书放再这 要重新申请一个新的把」——

## 签名机制（已查清）

三件套：`keystore.p12`（本地生成）+ `*.cer`（AGC 用 CSR 换）+ `*.p7b`（AGC 生成）。

工具是 `sdk/default/openharmony/toolchains/lib/hap-sign-tool.jar`，
子命令：`generate-keypair` / `generate-csr` / `sign-profile` / `sign-app` / `verify-app`。
hvigor 签名时也是调它（`ToolChainsConst.NEW_SIGN_TOOL = "hap-sign-tool.jar"`）。

`sign-app` 关键参数：`-mode localSign -keyAlias -keyPwd -appCertFile -profileFile
-inFile -signAlg SHA256withECDSA -keystoreFile -keystorePwd -outFile
-compatibleVersion 12 -signCode 1`。

## 🔴 实测排除：SDK 自带的 OpenHarmony.p12 签不了真机包

`lib/OpenHarmony.p12`（密码 `123456`，8 个别名）看着像"现成证书"，**实际不可用**：

- 应用证书别名（`openharmony application release` 等）是**自签的**（issuer == subject），
  不由 `OpenHarmony Application CA` 签发 → 拼三级-二级-根后报
  `verify certificate chain failed! Signature does not match.`
- 唯一带 2 级链的非自签别名是 `openharmony application ca`，能签成功，但 `verify-app` 报
  `verify permission signature failed, msg: Wrong key usage`（它不是软件签名证书）。
- 判断链长度的命令：`keytool -list -v -alias <a> -keystore OpenHarmony.p12 -storetype PKCS12 -storepass 123456`

**结论：必须申请华为开发者证书，无本地绕过路径。**

## 已验证：脚本链路本身没问题

用**自建 CA 链**（root → 中间 CA → 应用证书，`generate-ca` / `generate-app-cert`
还需 `-issuerKeystoreFile/-issuerKeystorePwd` 指定签发者密钥库）+
自签 Profile，完整跑通：

```
sign-profile success → sign-app success
→ verify: Verify success
→ verify codesign success / verify permission sign success
→ 证书链 3 级 / Profile bundle 正确
```

即：一旦拿到 AGC 的 .cer + .p7b，直接就能出可安装的包。

## ⚠️ 我先判断错了，纠正一下

大哥说"真机是鸿蒙 7.0"，我第一反应是**否认**（当时查到的官方清单最高只到

真相：**HarmonyOS 7.0 = API 26 = `26.0.0`**，三者是同一代次的三个名字。

- 华为开发者版本页面用 `26.0.0` 这种**开发者套件号**
- 活动页标题写的就是「**HarmonyOS 7（API 26）Developer Beta1**」
- 系统更新推送的是 `HarmonyOS 7.0.0.105 SP6`
- 配套 SDK 26.0.0 / DevEco Studio 26.0.0.821

**教训：官方"版本清单"页只列到 26.0.0 Beta1，不代表不存在更高版本号；
不要在信息不全时否定用户的一手观察（他手机屏幕上就写着）。**

## 版本号写法有重大变化

> 从 API 26.0.0 起，版本号统一用**语义化格式 `X.Y.Z`**，取代旧的 `X.Y.Z(N)`。

所以是 `"26.0.0"`，**不是** `"26.0.0(26)"`。旧的 `"5.0.0(12)"` 那种带括号的写法在新工程里已过时。

完整对照：5.0.0→API12 / 6.0.0→20 / 6.0.1→21 / 6.0.2→22 / 6.1.0→23 / 6.1.1→24 / **7.0→26**

## 已改的配置（全部实跑验证过）

设备：**nova 14 Ultra，型号代码 `MRT-AL10`**（在 26.0.0 支持机型清单里，
但属"可升级"而非首发预装）。

| 文件 | 字段 | 改前 | 改后 |
|---|---|---|---|
| `harmony/build-profile.json5` | `compatibleSdkVersion` | `5.0.0(12)` | `26.0.0` |
| 同上 | `compileSdkVersion` | 无 | `26.0.0` |
| 同上 | `targetSdkVersion` | 无 | `26.0.0` |
| `harmony/oh-package.json5` | `modelVersion` | `5.0.0` | `26.0.0` |
| `harmony/hvigor/hvigor-config.json5` | `modelVersion` | `5.0.0` | `26.0.0` |

### 为什么 compatibleSdkVersion 也该设 26（而不是压到 12）

压 `5.0.0(12)` 会真实触发两条编译警告 —— 这才是设错版本的证据：

- `Index.ets:137` `Circle().fill()` 是 **API 26** 才有的 API
- `ChannelServer.ets:186` `srv.close()` 是 **API 20** 才有的 API

报错形如：`API is supported since SDK version 26.0.0. However, the current
compatible SDK version is 5.0.0(12). It is recommended to use apiAvailable...`

改齐到 26 后两条警告**消失**。构建 `BUILD SUCCESSFUL`。

## 🔴 核心结论：改包名躲不过「缺私钥」

大哥问「能改成 `cn.zm.homegame.controller` 吗」。**能改**（只改
`harmony/AppScope/app.json5` 的 `bundleName`，`module.json5` 里没有这个字段），
但**改完仍然签不了** —— 因为签名要的是**私钥**，p7b 里没有私钥。

签 HAP 需要三样，缺一不可：

| 需要 | 现状 |
|---|---|
| `.p12` 私钥 | ❌ **没有**，必须从另一台电脑取回 |
| `.cer` 证书链 | ❌ 没有；若 p12 自带链可自行导出，否则还要 AGC |
| `.p7b` Profile | ⚠️ 有一个，但 bundleName 不匹配 |

**Profile 只是"授权声明"，不含私钥。** 这是最容易误解的点。

## 拿到 p12 之后的两条路

- **路线 A（推荐）**：保持 `com.carhi.carlifephone`，去 AGC **只建一个新 Profile**
  （可引用同一张证书 + 同一台设备），1 步操作。
- **路线 B（零 AGC）**：把 `bundleName` 改成 `cn.zm.homegame.controller`，
  直接用现有 p7b。**风险**：同包名 + 同证书 = 系统判定为**升级**，
  会**覆盖手机上的 HomeGame App**（数据可能丢）。测试可以，别长期用。
- **路线 C（不依赖旧机器）**：用我已生成的 `certs/carhi.csr` 去 AGC
  新建证书 + 新建 Profile，2 步操作，全部干净。**找不到 p12 就走这条。**

## 新增工具：`bash tools/sign.sh inspect [p12] [密码] [p7b]`

用途：拿到 p12 后立刻判断能不能复用。会输出别名、自带证书链长度、
