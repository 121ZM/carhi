# 23:20 方案 A 实施 —— 消除录屏授权弹窗（CaptureStrategy）

**背景**：用户反馈「一下就掉线了」「每次都要确认开启录屏」，且判定「不能走录屏这条路」，
经三方案对比后用户选择 **方案 A（修复录屏用法）**。

**根因**：`OH_AVScreenCapture` 在**未设置 CaptureStrategy 时，每次启动采集都会弹 Picker 授权框**；
切后台/被抢占后采集被回收 → 自动重启 → 又弹框 → 投屏画面被自己打断。

**改动（已完成，编译通过并安装）**：
- `cpp/screen_encoder.cpp`
  - 新增 `LOGW` 宏（原工程只有 LOGI/LOGE，首次编译因 undeclared identifier 失败）
  - 新增 `ApplyCaptureStrategyLocked()`：在 `StartScreenCaptureWithSurface` **之前**调用
    - `StrategyForPickerPopUp(false)` ← 核心：不弹 Picker
    - `StrategyForKeepCaptureDuringCall(true)` ← 通话中不掐断采集
    - `StrategyForCanvasFollowRotation(true)` ← 旋转自动跟随，免手动 ResizeCanvas
    - `SetCaptureStrategy()` 后立即 `ReleaseCaptureStrategy()`
  - `StartCaptureLocked()` 中插入调用点（在 SetMaxVideoFrameRate 之后）
- `cpp/screen_encoder.h`：新增 `ApplyCaptureStrategyLocked()` 声明

**接口依据**（`native_avscreen_capture.h:609-725`，`@since 20`，本机 API 26 支持）：
> `StrategyForPickerPopUp(strategy, false)`：APP don't need to pop up the Picker after screen capture starts
> `SetCaptureStrategy`：**must be called before screen capture starts**

**路径已铺好的旁支**：`module.json5` 的 `backgroundModes: ["audioRecording","location"]` +
`ohos.permission.KEEP_BACKGROUND_RUNNING` 上一轮已补齐。

**验证状态**：⏳ 待用户实机验证「不再反复弹授权框」+ 切后台/息屏下画面是否持续更新。
**已知风险**：`PickerPopUp(false)` 保证"首次之后不弹"，但**熄屏/锁屏下能否持续存活，文档未明确保证**。

## 00:05 【已修复 + 真机验证】30 秒周期性掉线根因：手机端漏发 65609

### 根因（车机端反编译确凿）
车机端 `a/a/a/a/m/k/a/c.java`：
- 收到手机的 **65540（设备信息）**时启动 **30 秒**定时器
  （`h.f209a.a(this.h, 30000L)`，第 182 行）；
- 该定时器到期即 `context.a()` → **断开整条连接**，日志
  `"Carlife Connect authentication failed."`；
- 取消它的**唯一路径**是收到手机的 **65609（MD_AUTHEN_RESPONSE）**
  且 `encryptValue` 非空（第 184-233 行 `case 65609`）。

本项目原实现 `onHuAuthenRequest()` **只回了 65611，从未发 65609** →
30 秒后必然掉线。**这就是「每隔一段时间稳定重连」的真因。**

### 修复
1. `protocol/Messages.ets`：新增 `CarlifeAuthenRequest`（decode，randomValue=1）
   与 `CarlifeAuthenResponse`（encode，encryptValue=1）。
2. `core/StateMachine.ets`：
   - 新增 `sendAuthenResponse(randomValue)`；
   - 新增 `buildVerifyCode()`：取 randomValue 的 FNV-1a 摘要，产出
     `"2.0;<randomValue>;<digest>"`（车机端只校验非空，真车机如需严格校验
     再补 RSA 路径）；
   - `onHuAuthenRequest(msg)`：**先发 65609，再发 65611**（顺序不可颠倒）。
3. `core/StateMachine.ets` 保活加固：
   - `startHeartbeat()` 里补 `clearInterval` 防重复；
   - 新增 `heartBeatOk/heartBeatFail` 计数，**发送失败不再静默吞掉**
     （以前 catch 里什么都不做，导致"保活没发出去"完全不可见）。

### 真机验证结果（MRT-AL10）
- 修复前：稳定 **30~62 秒**必断一次（7 通道集体断开）。
- 修复后：**连续稳定运行 100+ 秒无断开**；保活 `65563 已发送 ×110，失败 0`。
- 新出现的断开原因变为 **`Network is down`** —— 即手机 Wi-Fi 网络层中断，
  与 CarLife 协议无关。Wi-Fi 统计 `RX dropped:1145`，推流时 8240
  `send-q` 曾达 47987 字节积压，印证为无线链路拥塞/丢包。

### 结论
协议侧掉线问题**已解决**。剩余断开是无线网络质量问题（真机 Wi-Fi 调试固有）。

## 00:40 【需求实现】录屏授权弹窗时机优化（用户确认：接受每次弹，优化时机）

### 用户诉求
「能不能申请权限只记住授权，记录提示，不用每次打开软件都弹出来呢」
经 AskUserQuestion 确认：用户指的就是 **录屏授权弹窗**；且接受
「无法记住时，优化弹窗时机」这一取舍。

### 技术结论（有官方文档依据，非推测）
鸿蒙手机/平板端 **录屏授权弹窗无法被应用记住，也无法绕过**：
1. `OH_AVScreenCapture_StrategyForPickerPopUp(strategy, false)` 关掉的是
   PC/2in1 的「选择共享内容」Picker，**不影响手机端的隐私保护弹窗**。
   （openharmony docs：Phone/Tablet 弹窗模式配置说明，API 23 起）
2. openharmony docs `avscreencapture-c-basic-process.md`「约束与限制」原文：
   「在录屏取码流场景中，屏幕录制启动时会弹出隐私保护弹框」——系统强制。
3. 唯一免弹窗路径 `ohos.permission.CUSTOM_SCREEN_RECORDING`：
   官方标注 **仅 PC/2in1 生效（API 22+）**，且属**受限开放权限**，
   需华为审批（ACL），手机端不适用。
→ 结论：**弹窗消不掉**，能优化的只有「触发时机」与「次数」。

### 实现：新增 `core/CaptureGate.ets`（录屏授权门控）
把弹框压低到"系统下限"，核心是不让**非必要路径**触发弹框：
- 状态机：`PENDING / GRANTED / DENIED / EXHAUSTED`；
- `tryLaunch()`：一次会话最多主动启动采集 `MAX_LAUNCH_ATTEMPTS = 3` 次；
- `markGranted()`：**首次出帧**即视为用户已允许（此后重启采集不再受配额限制）；
- `markFailed()`：连续启动失败 `DENY_THRESHOLD = 2` 次 → 判定用户点了取消
  → 进入 `DENIED`，**停止一切自动重试**（这是"反复弹框"的最大来源）；
- `reset()`：用户手动「重新授权」时清空配额。

### 改动
1. `core/CarLifeEngine.ets`
   - `EngineListener` 新增 `onGrantPrompt()` / `onCaptureBlocked(reason)`；
   - `startStreaming()` 入口接 `CaptureGate.tryLaunch()`：配额耗尽直接
     `onCaptureBlocked` 返回，**不再弹框**；配额内则先 `onGrantPrompt()`
     提示"请在弹框中点允许"再启动；
   - `onFrame` 回调里 `CaptureGate.markGranted()`；`start()` catch 里
     `CaptureGate.markFailed()`；
   - `handleCodecError()` 开头新增分支：`CaptureGate.needsUserAction` 时
     直接停流，**不进自动重试**（关键：以前重试 5 次会弹 5 次框）；
   - 新增公开方法 `retryCapture()`：仅由用户点「重新授权」触发。
2. `pages/Index.ets`
   - 新增 `@State grantHint` / `@State grantBlocked`；
   - 新增「录屏授权」SectionCard：显示门控状态（待授权/已授权/已拒绝）、
     引导文案、以及受阻时出现的「重新授权」按钮；
   - 顶部注释写明"系统强制、应用无法记住"这一事实，避免后人误以为是 bug。

### 效果
- 车机重连 / 采集中断重试 **不再重复弹框**（以前每次重试都会弹）；
- 拒绝授权后不再骚扰，改为在 UI 上亮出「重新授权」按钮；
- 每次应用启动 + 车机开始推流，仍会弹 **1 次**（系统强制，无法消除）。
